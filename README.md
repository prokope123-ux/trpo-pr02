# Практическая работа №2. CSS, адаптивная вёрстка и SCSS

Дисциплина «Технологии разработки программного обеспечения», 3 семестр, 2026–2027 гг.
Преподаватель: Макиевский С. Е.

## Что получилось

Адаптивный **каталог курсов кафедры**: шапка, панель фильтров слева, сетка из 12 карточек справа, информационный блок и подвал. Стили написаны на SCSS и компилируются в `css/styles.css`. Фильтры по категории и уровню работают на чистом CSS (`:has()`), без JavaScript.

Технологии: HTML5, CSS Grid, Flexbox, SCSS (Dart Sass 1.x, модули `@use`).

## Запуск

Требования: Node.js 18+ и npm. Для просмотра страницы Node не нужен, а для пересборки стилей нужен.

```bash
git clone https://github.com/prokope123-ux/trpo-pr02.git
cd trpo-pr02
npm install                # ставит Sass
npm run build              # разовая сборка: scss/styles.scss → css/styles.css
npm run watch              # режим наблюдения: пересборка при каждом сохранении SCSS
```

Откройте `index.html` в браузере. Скомпилированный `css/styles.css` уже лежит в репозитории, поэтому для просмотра достаточно открыть страницу.

## Использование dataset

| Файл | Где используется |
|---|---|
| `data/catalog.csv` | 12 карточек: одна строка = один `article.card`. `category` → бейдж, `level` и `hours`, `seats`, `rating` → метаданные, `image` → картинка, `description` → текст. Итоги в блоке «О каталоге» (12 курсов, 344 часа) посчитаны по столбцам файла |
| `data/theme.json` | значения перенесены в `scss/_variables.scss`: `colors` → `$color-*`, `radius` → `$radius`, `spacing` → `$space-*`, `container` → `$container-width`, `fontFamily` → `$font-family` |
| `images/product-01..03.svg` | картинка карточки; одна на категорию (Frontend, Backend, Инструменты) |

## Что и где изменилось по шагам

- **Шаг 5, рабочий CSS.** Сначала раскладка была написана обычным CSS (коммит `style: add working layout in plain CSS...`): Grid для страницы и карточек, Flexbox для шапки.
- **Шаг 6–7, SCSS и переменные.** Стили разнесены на partial-файлы, повторяющиеся цвета, отступы, радиус и ширина контейнера вынесены в `_variables.scss`. Значение больше нигде не дублируется.
- **Шаг 8, вложенность.** Используется БЭМ-вложенность через `&__element` и `&:hover`, глубина не больше трёх уровней (например, `.card` → `&__meta` → `dt`). После этого шага код карточки читается одним блоком вместо десятка плоских селекторов.
- **Шаг 9, mixin.** Четыре миксина (см. ниже). Тройка «фон + рамка + радиус» повторялась в карточке, панели фильтров и инфоблоке, теперь это один `@include surface`.
- **Шаг 10, функция.** `rem($px)` в `_functions.scss` переводит пиксели в rem (`rem(240)` → `15rem`). Применена для минимальной ширины карточки, ширины боковой панели и картинки на мобильном.
- **Шаг 12, адаптивная сетка.** `grid-template-columns: repeat(auto-fill, minmax(rem(240), 1fr))`: на 1440 px три колонки, на 768 px две, на 375 px одна.
- **Шаг 13, два breakpoint** (карта `$breakpoints`, миксин `respond`):
  - `laptop` (960 px): панель фильтров переносится над каталогом, группы фильтров встают в ряд;
  - `mobile` (600 px): карточки становятся горизонтальными (картинка слева, описание скрыто), навигация в шапке встаёт под логотип.

## Где применён mixin

| Mixin | Что делает | Где используется |
|---|---|---|
| `respond($name)` | медиазапрос по имени точки из `$breakpoints` | `_layout`, `_header`, `_card`, `_filters` |
| `focus-ring` | кольцо фокуса для клавиатуры | `_base` (ссылки, поля, кнопки) |
| `surface($padding)` | фон, рамка и скругление | `.card`, `.filters__form`, `.info` |
| `container` | контейнер ограниченной ширины | `.container` |

Ещё в SCSS использованы циклы `@each`: по карте `$categories` генерируются модификаторы `.badge--frontend/backend/tools` и правила фильтрации, по списку `$levels` — правила для уровней.

## Чем SCSS-переменная отличается от CSS custom property

- **SCSS-переменная** (`$color-accent`) существует только при компиляции: Sass подставляет значение и в итоговом CSS её уже нет. Её нельзя изменить в браузере, зато можно использовать в вычислениях, циклах, картах и условиях.
- **CSS custom property** (`--color-accent`) живёт в браузере: наследуется по DOM, меняется через DevTools и JavaScript, может быть разной в разных блоках страницы (например, для тёмной темы).
- Здесь значения темы нужны на этапе сборки (генерация модификаторов, функции, миксины), поэтому использованы SCSS-переменные. Если понадобится переключение темы на лету, их можно продублировать как custom properties.

## Зачем нужны partial-файлы

Файл с подчёркиванием (`_card.scss`) не компилируется сам по себе, а подключается через `@use` в `styles.scss`. Это даёт разделение по ответственности (variables, base, layout, components), удобную навигацию по проекту, отсутствие одного огромного файла и изоляцию: каждый partial явно подключает только то, что использует.

## Сравнение SCSS и итогового CSS

`css/styles.css` (≈375 строк) — результат компиляции ≈500 строк SCSS (вместе с комментариями): вложенные правила развёрнуты в плоские селекторы, переменные заменены значениями, миксины раскрыты, циклы превращены в отдельные правила (`.badge--frontend` и т. д.). Правки вносятся только в `scss/`, после чего запускается `npm run build`.
